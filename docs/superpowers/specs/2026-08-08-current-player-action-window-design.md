# 当前行动玩家动作窗口设计

## 目标

让实时助手和视频复测只处理状态机当前行动玩家的出牌区域，删除不必要的 `WAIT_CLEAR` 和人工确认阻断，同时保留足够的动画稳定与多帧共识保护。

## 行为约束

- 当前回合只识别 `snapshot.current_player` 对应的区域，不扫描其他玩家的出牌区域。
- 右家动作提交后，下一次分析只处理下一位行动玩家；右家残留牌不会再次进入识别入口。
- 不设置“等待当前区域清空”的状态。
- 当前区域出现内容变化后，等待内容稳定，再进行有限次数的识别采样。
- 稳定的出牌或“不出”结果经过共识和规则校验后才能提交。
- 识别不到动作、动画未稳定或等待超时只记录重试诊断，保持当前行动玩家和运行状态，不进入人工确认。
- 事后纠错接口保留，作为异常结果已经提交后的修正手段，不参与正常流程。
- 复测状态机管线使用与实时相同的动作窗口、超时和自动重试配置；视频只是输入来源，复测不调用 DanZero。

## 简化后的动作窗口

动作窗口只保留三个阶段：

1. `WAIT_ACTION`：当前玩家区域相对激活时基线没有新变化，继续等待。
2. `SETTLING`：检测到内容变化或明确“不出”标志，等待动画停止。
3. `BURST_READ`：采样当前玩家区域，交给现有 `BurstConsensus` 和 `LiveReducer`。

采样期间如果内容再次变化，清空本轮样本，回到 `SETTLING`。不再保留 `WAIT_CLEAR`、`VALIDATE` 和 `REVIEW_REQUIRED` 作为动作流程阶段。

## 超时与错误恢复

动作超时不提交猜测动作。编排器写入一次 `recognition_retry` 生命周期事件并重置当前动作样本，随后继续等待同一个玩家的动作。重复超时由 incident occurrence 聚合，避免每帧产生新事件。

## 复测模式

- “状态机管线”不再设置 `sample_every_frame=True`，不绕过动作窗口。
- “可信日志驱动”继续把可信日志动作送入相同的提交、换手和 DanZero 请求路径，只跳过视觉识别。
- “逐帧比对”继续作为单独的识别结果对比工具。

## 测试验收

- `ZoneLifecycle` 不再产生 `WAIT_CLEAR`，初始激活后直接等待当前动作变化。
- 同一玩家区域没有新变化时，不会重复提交上一动作。
- “不出”标志可在当前行动玩家区域中被采样和提交。
- 动画中内容持续变化不会提交动作；稳定后才进入共识。
- 动作超时保持运行并重试，不返回人工确认状态。
- 视频状态机管线使用完整动作窗口；可信日志仍能驱动 DanZero 建议。
