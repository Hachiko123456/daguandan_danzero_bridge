# 实时对局超级加倍阶段保护设计

## 目标

复用现有 `super_double.png` 模板识别结果，在实时 DanZero 对局进入“超级加倍”界面时暂停出牌识别链路，页面显示“正在决定是否加倍”，避免把加倍界面误判成首手“不出”或普通出牌。

## 范围

- 仅修改实时对局的运行中识别管线和实时助手页面状态显示。
- 复用现有 `FastSignalResult.super_double_visible`，不新增按钮、不新增用户操作。
- 保留现有 `waiting_lead` 对加倍阶段的处理逻辑。
- 不改变可信日志复测的输入、状态机驱动方式或 DanZero 请求策略。

## 行为设计

实时管线在 `running` 状态完成快速信号识别后，优先判断 `super_double_visible`：

1. 为真时，清理当前尚未形成共识的出牌采样和“不出”稳定计数。
2. 直接返回当前状态更新，不进入区域生命周期、出牌区域识别、共识提交或建议请求流程。
3. 页面将状态显示为“正在决定是否加倍”，并提示加倍按钮存在期间不进行出牌识别。
4. 不创建人工确认请求，不写入玩家出牌/不出牌事件，不推进回合和牌局状态。
5. 后续帧检测不到超级加倍按钮后，自动回到原有实时识别流程。

这里不把“正在决定是否加倍”建模成新的持久状态，避免扩大状态机和复测协议；它是由当前帧快速信号驱动的展示状态。

## 边界与安全性

- 加倍按钮出现时，即使其他模板同时误识别出 `passed` 或 `first_play`，也以加倍信号为优先，不允许这些候选进入共识。
- 加倍按钮消失后，不复用加倍期间积累的旧采样，防止延迟提交过期识别。
- `waiting_lead` 的行为保持不变：有超级加倍按钮时继续等待首出标志，不调用首发玩家识别。

## 验证

至少覆盖以下回归场景：

- `running` 状态检测到超级加倍：保持牌局状态和事件列表不变，不调用出牌识别，不产生 review，不请求 DanZero。
- 超级加倍按钮消失：实时管线恢复原有出牌识别。
- 页面收到带 `super_double_visible` 的更新：显示“正在决定是否加倍”；按钮消失后恢复普通状态文案。
- 既有 `waiting_lead` 加倍阶段测试和可信日志复测测试继续通过。

## 验收标准

在真实实时对局中，画面存在超级加倍按钮时，助手不会再显示“需要人工确认”，不会把左家第 1 手判成“不出”，不会推进牌局，也不会请求 DanZero；按钮消失后无需点击继续即可恢复实时检测。
