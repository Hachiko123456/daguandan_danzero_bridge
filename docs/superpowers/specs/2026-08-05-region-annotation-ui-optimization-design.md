# 区域标注界面优化设计

## 目标

优化“区域标注”页面的编辑体验：用户选择录制图片后立即看到图片预览；名称和角色通过下拉框选择，并始终以中文展示；删除区域标注界面中的来源图片字段，同时保持现有区域配置和识别逻辑的内部英文标识不变。

## 现状与约束

- 当前页面从 `screenshots` 目录递归读取图片，并通过 `AnnotationService` 加载 20 个区域配置。
- 区域配置内部名称使用英文稳定标识，例如 `my_hand`、`left_play`；角色值使用 `hand`、`play`、`anchor`、`generic`。
- 当前图片切换后只有在选择区域时才会尝试绘制预览，未选择区域时无法看到原图。
- 当前编辑表单使用文本框编辑名称，并包含来源图片文本框；表格也展示英文名称、英文角色和来源图片。
- 不能破坏现有区域的坐标、比例坐标、模板资源和 DanZero 逻辑。

## 方案选择

采用“界面和存储一起清理”的方案：

1. UI 不再提供来源图片表格列或编辑控件。
2. 服务层读取旧配置时忽略历史 `source_image` 字段，保存时不再写入该字段。
3. 已有区域名称和角色的英文值继续作为内部 key，UI 使用中文 label 显示。
4. 不引入拖拽绘制、自动识别或自动追踪等超出本次范围的交互。

## 中文显示映射

名称下拉框和区域表格使用以下固定映射，内部数据仍保存左侧英文 key：

| `first_play_self` | 己方首出牌提示 |

## 交互设计

### 图片预览

- 图片下拉框继续显示相对于 `screenshots` 根目录的相对路径。
- 用户切换图片后，服务读取该图片并立即渲染到预览区域。
- 没有选中区域时显示原图；选中一个或多个区域时，在原图上叠加对应彩色边框和中文名称。
- 选择表格行、切换图片或点击“标注选中区域”都会刷新预览。
- 找不到图片或图片读取失败时，预览区域显示可读的中文状态，不抛出未处理异常。

### 区域编辑

- 表格列调整为“名称、角色、绝对坐标、比例坐标”，移除“来源图片”。
- “名称”控件改为下拉框，选项使用上述中文 label，item data 保存英文 key。
- “角色”控件继续为下拉框，但表格和控件均使用中文 label，item data 保存英文 role value。
- 删除“来源图片”编辑控件。
- 编辑保存仍要求只选中一个区域；名称可以从固定名称列表中选择，服务层校验不能产生重复名称。
- 保存后重新计算 `ratio_box`，刷新表格和当前预览。

## 数据流与边界

`AnnotationPage` 负责控件状态、中文 label 和预览刷新；`AnnotationService` 负责区域配置解析、名称/角色值校验、坐标换算和 JSON 持久化。服务层不依赖 PySide6。

更新接口调整为：

```python
AnnotationService.update_region(
    old_name: str,
    *,
    name: str,
    role: str,
    box: Box,
) -> RegionRecord
```

`RegionRecord` 不再暴露 `source_image`；读取旧配置时允许该键存在但丢弃它，保存后的 `regions_config.json` 不再包含该键。其他配置字段和 schema version 保持不变。

## 错误处理

- 名称不在固定名称列表、角色不在固定角色列表、名称重复、坐标无效或超出 1280×720 时，保存失败并在状态栏显示中文错误。
- 没有图片时，图片预览显示“暂无可预览的录制图片”。
- 没有选择区域时，图片仍然正常显示原图；只有在需要叠加标注时提示用户选择区域。

## 测试策略

- 服务测试验证：中文映射存在且内部 key 不变；旧 `source_image` 可读取但保存后不再写入；名称/角色校验；重命名和重复名称失败；坐标比例换算继续正确。
- 页面测试验证：图片切换后即使没有选择区域也有非空 pixmap；表格不包含来源图片列；名称/角色控件是下拉框且展示中文、携带英文 data；表格展示中文 label；多选叠加和单选保存仍可用。
- 运行完整 pytest、Python 编译检查和 Qt offscreen 构造测试。
