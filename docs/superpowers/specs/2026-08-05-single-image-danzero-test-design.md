# 单图状态标注与 DanZero 测试设计

## 背景

当前截图页已经支持图片预览、区域配置和模板裁剪，但模板坐标反馈不够明显，模板标签只能输入，状态栏还重复显示当前图片。项目现有 DanZero 接口接收人工确认的 `GuanDanState`，仓库没有 OCR 或牌面识别依赖。

## 交互设计

### 预览页

- 图片下拉框保留作为当前图片选择器；删除状态栏中的“已预览：文件路径”，避免同一信息重复展示。
- 模板 ROI 更新后，坐标框和状态提示优先显示当前 ROI，不被普通图片预览状态覆盖。
- 模板类型继续使用中文下拉框。
- 模板标签改为可编辑下拉框：下拉列表展示历史标签，同时允许输入新标签；保存成功后新标签进入候选列表。
- 增加“单图标注 / 测试 DanZero”按钮，仅在存在当前图片时可用。

### 单图状态标注窗口

按钮打开独立窗口，显示当前截图和结构化表单。首版采用人工确认模式，不伪装成自动识别：

- 牌局上下文：当前级牌、百搭牌级别、当前行动者、本轮首出者。
- 我的手牌：空格分隔的内部牌码，例如 `3S 4H 5D`。
- 本轮事件：玩家下拉框、动作下拉框（出牌/不出）、牌码输入框，支持添加和删除多条事件。
- “构建参数”按钮校验表单并显示 `GuanDanState` 摘要。
- “测试 DanZero”按钮在工作线程中构建状态并调用 `DanzeroAdvisor.recommend`，显示推荐动作、牌型、耗时、状态摘要和可审计的 engine input JSON。

后续若加入 OCR/视觉模型，只替换表单的输入来源，状态校验和 DanZero 调用保持不变。

## 数据流

```text
当前截图 → 单图标注窗口人工确认 → GuanDanState
        → readiness 校验 → OneShotWorker → DanzeroAdvisor
        → LocalAdvice + engine_input → 结果面板
```

DanZero 调用失败、状态不完整、依赖缺失和策略异常都显示在结果面板，不阻塞主窗口；按钮在调用期间禁用。

## 测试策略

- UI 回归测试验证没有重复“已预览”状态、模板标签可下拉/输入、拖框更新模板坐标。
- 状态构建测试验证表单能生成 `GuanDanState`，玩家事件和不出事件保持正确顺序。
- 测试按钮使用注入的 advisor 验证构建参数、异步成功和异常提示，不依赖真实模型耗时。
- 运行完整 pytest、compileall、PySide6 栈审计和主窗口冒烟测试。
